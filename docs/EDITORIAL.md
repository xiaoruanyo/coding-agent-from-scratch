# 教材编写规范：像教科书一样严谨，像老师一样好懂

## 1. 本书写给谁？

读者具备基本编程能力，能理解函数、列表、字典、异常和调用栈，但不要求会 Agent，也不要求精通 Python。默认 Windows + PyCharm 读者可以跟着运行；命令同时尽可能避免依赖特定 IDE。

**不使用不必要的 Java 类比**，不为了术语堆术语。

## 2. 每课必须解决真实问题

不从“今天学习 API X”开始，而从读者能感知的疑问开始。

示范：

- 不好：“第 6 课 Reducer API。”
- 更好：“节点已经能返回 State 更新，为什么多个分支更新同一字段时还需要 Reducer？”
- 不好：“第 18 课 Command。”
- 更好：“当一个节点既要更新 State 又要选择下一步，为什么普通边有时不够顺手？”

先提出错误直觉，再给证据和运行过程，最后才是 API。

## 3. 一章建议包含的教学模块

1. **学前位置**：这课建立在哪些知识上？会用在哪项最终产品功能？
2. **具体问题与朴素直觉**：为什么不能只用更简单的方法？
3. **最小实验**：让一个关键机制独立出现。
4. **逐行解析**：解释输入、执行步骤、State 更新和结果，而不是只贴代码。
5. **运行现象与验证**：要观察什么、正常输出是什么、哪里可能不固定。
6. **反例／错误排查**：故意展示会出错的情况，并解释根因。
7. **适用边界与工程取舍**：什么时候用，什么时候不值得用。
8. **落回产品主线**：这项机制最终支持哪一个 UI 或 Core 的真实功能。
9. **理解检查**：让读者判断具体场景，而非背定义。

不是每课都需要大量习题；重复练习会破坏教学节奏。关键难点应该有简短但尖锐的思考题。

## 4. 代码分级

| 标记 | 含义 | 编写要求 |
|---|---|---|
| **可运行实验** | 有完整文件和具体命令 | 指定依赖、入口、预期行为，尽量配自动测试 |
| **局部片段** | 只展示某个 API 的关键几行 | 明确“片段”，不能宣称直接运行 |
| **架构伪代码** | 解释职责或路由策略 | 必须明确不是完整实现 |
| **外部模型实验** | 依赖第三方 API | 明确 Key、网络、费用以及输出不确定 |

任何被称为“已经验证”的示例必须有实际执行的证据；不能用对代码的静态阅读替代运行验证。

## 5. 分清框架事实、课程约定与设计意见

例如：

- **框架事实**：`interrupt` 可以暂停 Graph，通过 `Command(resume=...)` 恢复，并需要 Checkpointer。
- **课程约定**：V1 写文件必须人工审批、累计第三次普通测试 FAIL 后停止。
- **设计取舍**：我们为了简化 V1 暂时采用整批审批，也可以设计更细粒度执行。

把课程自主定义的 Tool schema 或业务规则写成“LangGraph 自带行为”属于严重质量问题。

## 6. 不遗漏安全和状态语义

技术教材不能为了缩短篇幅省略：

- `TypedDict` 不提供运行时字段默认值；
- `AIMessage.tool_calls` 不是工具已执行；
- ToolMessage 必须与原调用 ID 正确对应；
- 并行任务没有自动的业务依赖顺序；
- `interrupt` 可能导致节点前置代码重新运行；
- Checkpoint 保存现场，不等于当前模型能看到全部历史；
- 测试通过与当前工作区版本必须对应；
- 工具读写必须守住单次硬边界；
- 失败、超时、未执行、审批拒绝不混为“普通失败”。

## 7. 语言和篇幅

全书以简体中文为主。首次出现专业术语用“中文名（英文原词）”，后续在不引起歧义的前提下优先中文解释。API 名与代码保持原英文。

**不人为设每课 2000 字上限。** 简单概念写到讲清为止；复杂机制可以拆成连续的多课，避免一章同时讲透十个主题。禁止靠重复定义凑字数。

## 8. 跨章节编校

- 上一课已经详细讲过的知识，不必逐字再讲，应提供短回顾和链接。
- 同一概念术语一致：LLM、Tool、Graph、State、Checkpoint、Context、Runner、Harness。
- 每章“下一课”链接必须指向真实存在的文件；未写完时只描述下一主题，不造死链接。
- 所有正文至少经一次校对；教程代码有语法检查或测试记录。
- 每轮提交列明已完成、仍未完成和验证范围。
- 新增能力必须更新本书唯一的课程导航与产品验收契约。

## 9. 不再重复以前的失误

旧版最主要的问题不是字数不够，而是**把聊天节奏机械映射为课程节奏，以及把复习笔记的写法当成教材正文**。

新结构必须把旧对话中的有价值问题变成章节素材，再按知识依赖重新组织。

最终要让读者在没有参与原对话的情况下，也可以独立跟学并理解每一步。
