# 毕业标准：证明它是一个完整的小型 Coding Agent 产品

> **这不是“代码跑起来就算通过”的作业清单，而是整个 Web UI → HTTP → Graph → Tool → 真实文件／测试 → UI 的端到端验收合同。**

## A. 用户能使用的产品体验

- [ ] 前端能够启动，显示当前工作区、任务输入框、任务状态及错误提示。
- [ ] 后端能够启动，提供健康检查、任务创建、任务查询和审批接口。
- [ ] 可以在本地单用户模式选择或配置一个明确授权的工作区。
- [ ] 输入任务后出现唯一 task_id，并能看到真实工作流程事件。
- [ ] 用户能查看一次实际的文件修改 Diff（至少文本前后对比）。
- [ ] 用户能批准、拒绝某一次具体修改，页面正确反映结果。
- [ ] 页面能展示真实测试结果、失败原因、最终报告。
- [ ] 刷新页面之后重要任务状态可以重建；重启进程后的恢复能力依赖持久化 Checkpointer 与 Task Store，应在宣称“可恢复”之前实测。
- [ ] 浏览器、后端、执行层对成功/失败/未验证的语义一致。

## B. Agent 真实能力

- [ ] 能列出项目目录（受深度和条数限制）。
- [ ] 能根据关键词搜索项目代码，不把整个 Repo 一次性喂给 LLM。
- [ ] 能有限读取文件，返回行号和大小限制信息。
- [ ] 对已有文件可提出精确修改，不做无条件覆盖。
- [ ] 修改前可以生成可读的审批内容，包含文件名和具体改动。
- [ ] 用户批准后执行的调用参数与获批参数一致。
- [ ] 可以运行明确受限的 pytest，并获取退出码、输出与超时信息。
- [ ] 能正确对应多个 tool_call_id 和每个真实/未执行的结果。
- [ ] 能在测试失败后继续分析，或在次数上限/其他错误下正确停止。

## C. 安全与状态不变量（必须自动测试）

- [ ] 对授权 workspace 之外的读取/写入路径明确拒绝。
- [ ] 对尝试经符号链接逃逸的路径明确拒绝。
- [ ] `replace_text` 的旧文本匹配 0 次或多次都不能写入。
- [ ] 用户拒绝修改后，文件字节内容未变化。
- [ ] 审批不能被“模型换一组新的工具参数”绕过。
- [ ] 任务取消后不得继续发起新的文件写入。
- [ ] 每一个 Tool Call 都有真实结果或明确的未执行结果。
- [ ] 测试 FAIL 与 TIMEOUT 不混计。
- [ ] 第三次普通测试 FAIL 后停止自动修复（采用课程规定的计数口径）。
- [ ] 任何新的写入都会使旧测试通过证明失效。
- [ ] 没有真实 PASS 记录就不能宣布 SUCCEEDED。
- [ ] 工具出错、服务端异常、前端断网不会直接转成“成功”。

## D. 工程质量

- [ ] 后端模块分层清楚：API、Runner、Agent Core、Tool、State、Policy。
- [ ] 核心 Tool 与 Guard 有单元测试。
- [ ] 至少存在一个无需真实 LLM 的集成测试，模拟 Tool Calls 与审批。
- [ ] 至少存在一个在临时仓库上执行的端到端测试。
- [ ] 类型检查、Python 语法检查、测试和前端构建有可复现命令。
- [ ] 日志和 UI 不输出真实 API Key。
- [ ] 项目有一份能够按步骤在干净机器上启动的中文说明。
- [ ] 失败状态的“已完成步骤”和“未完成事项”对用户可见。

## E. 高价值故障注入测试

1. **审批拒绝**：发起写入，拒绝，检查文件哈希不变。
2. **过期上下文**：模型打算替换的 `old_text` 已改变，必须拒绝精确替换。
3. **同批工具部分失败**：先读成功、修改失败、后续依赖测试跳过，全部调用 ID 都有结果。
4. **模型自称成功**：不执行测试，LLM 宣称已完成；UI 不得显示“测试通过”。
5. **测试后再修改**：先 PASS 后成功写入；旧 PASS 不再证明当前版本。
6. **测试超时**：时间限制触发 TIMEOUT，不消耗普通 FAIL 预算。
7. **恢复重放**：审批前暂停，恢复时不能重复执行此前已完成的文件写入。
8. **过期连接**：关闭页面、重新打开任务，状态应依据服务器持久状态重建，而不是 UI 猜测。

## F. 何时可以宣布“完成 Mini Coding Agent V1”？

不是看仓库有多少行代码，而是：

> **从浏览器发起一次真实代码修复，在明确授权的工作区内经过审批完成实际文件修改，运行真实测试，再在同一界面查看可追溯结果，且上述关键安全不变量和失败路径经过验证。**

只实现一张 Graph、打印 ToolMessage、拥有一个漂亮网页，但尚未完成真实执行与验证闭环，都不能宣布产品毕业。

## G. 扩展课程不属于 V1 必修验收

完整 Git 操作、编辑器集成、生产级多租户隔离、远程沙箱、容器集群、向量 RAG、多 Agent 调度、GitHub 自动 PR、MCP/Skills 插件化、精细成本治理等可以后续扩展。先证明小体量、完整闭环的产品可信。
